# Harbour Hub documentation

This directory is the human-readable documentation for the Harbour Hub backend. The code is the
source of truth: every document here describes behaviour that exists today, and any gap is called
out as debt rather than described as if it were built.

---

## Where to start

| You want to… | Read |
|---|---|
| Call the API for the first time | [`api/README.md`](api/README.md) — auth, conventions, money, status enums |
| See one real request and response per flow | [`api/examples.md`](api/examples.md) — end-to-end worked examples |
| Look up a path, method, or payload | [`api/endpoints.md`](api/endpoints.md) — generated from `schema.yml` |
| Find the exact text of an error or success message | [`api/messages.md`](api/messages.md) — catalogue pinned by tests |
| Understand the entities and the money rules | [`data-model.md`](data-model.md) — models, invariants, status machines |
| Seed a local dataset | [`sample-data.md`](sample-data.md) — what `create_sample_data` builds and how to run it safely |
| Browse the contract interactively | `http://localhost:8000/api/docs/` (Swagger UI) or `/api/redoc/` |

The four API documents are ordered deliberately. `api/README.md` explains the shared conventions,
`api/examples.md` shows them applied, `api/endpoints.md` is the exhaustive lookup table, and
`api/messages.md` is the exact-string reference used by the test suite.

## Source of truth

| Artefact | Path | Notes |
|---|---|---|
| OpenAPI contract | [`../schema.yml`](../schema.yml) | Generated by `drf-spectacular`. Commit it with the code that changes it. |
| Models | `apps/*/models.py` | The database schema and every `TextChoices` enum. |
| Endpoint behaviour | `apps/*/views.py`, `apps/*/serializers.py` | Status codes and message strings. |
| Money movement | `apps/commerce/services/`, `apps/financials/services.py` | Payment finalisation, earning accrual and release, refunds, payouts. |
| Endpoint reference | `scripts/generate_api_reference.py` | Deterministic renderer for `api/endpoints.md`. |

If a document and the code disagree, the code wins and the document is a bug.

## Keeping the docs correct

When the API surface changes:

```powershell
python manage.py spectacular --file schema.yml
python manage.py spectacular --file schema.yml --validate
python scripts/generate_api_reference.py
```

Then:

1. Commit `schema.yml` and `docs/api/endpoints.md` together.
2. Update `api/messages.md` and `api/examples.md` for any new or changed message or flow.
3. Update `data-model.md` for any model, invariant, or status-machine change.
4. Update `sample-data.md` if `create_sample_data` changes what it creates.
5. Run the full gate (below) before committing.

### Full gate

```powershell
python manage.py check
python manage.py makemigrations --check --dry-run
python -m pytest -q
python -m flake8 apps hb tests --select=F401,F821,F841 --exclude=migrations
python manage.py spectacular --file schema.yml --validate
```

`flake8` is not on `PATH` in this environment; invoke it as `python -m flake8`.

## Conventions used in these documents

- Money is written as a decimal string with two places, for example `"250000.00"`.
- Amounts are stored in NGN. Display conversion is separate and never changes stored money; see
  [`api/README.md`](api/README.md#money).
- Timestamps are ISO 8601 UTC.
- `order_id` / `id` is the API key. `order_number` is display-only.
- Identifiers in the examples come from the sample dataset or are illustrative; a real run
  generates different values.
- Known limitations are labelled as debt, not omitted. The current list is in
  [`superpowers/plans/P4-COMPLETE.md`](superpowers/plans/P4-COMPLETE.md).
